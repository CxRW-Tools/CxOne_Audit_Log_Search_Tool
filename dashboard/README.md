# CxOne Audit Log Dashboard

Interactive single-page dashboard for Checkmarx One audit-log exports. Produces a self-contained `dist/index.html` (all JS/CSS inlined) that loads data at runtime — the same build can serve any tenant's export.

---

## Quick start

```bash
npm install

# 1. Ingest a raw audit export (UTF-16LE .log from CxOne)
npm run ingest -- path/to/audit.log

# 2. Build the single-file bundle
npm run build

# 3. Serve the dist/ directory alongside the data file
#    (any static server works — the bundle fetches ./data/audit.json)
npx serve dist
```

Point your browser at `http://localhost:3000`. The bundle fetches `./data/audit.json` on load. Use `?data=<url>` to point at a different file.

## Ingest script

Reads a raw CxOne audit export (UTF-16LE, CRLF) and writes `public/data/audit.json`:

```bash
npm run ingest -- <path-to-audit.log>
# Override output path:
npm run ingest -- <path-to-audit.log> --out /some/other/path/audit.json
```

The generated JSON is dictionary-encoded (types/users as sorted index arrays) to keep file size small (~1–2 MB for ~12k events).

---

## Runtime data loading

The app also accepts files dropped directly into the UI without a page reload:

- **`.json`** — a pre-generated `audit.json` in the schema described below
- **`.log` / `.txt`** — a raw CxOne export; parsed in-browser with UTF-16LE/UTF-8 detection

---

## Deploying a specific export

```
your-web-root/
├── index.html          ← dist/index.html (the self-contained bundle)
└── data/
    └── audit.json      ← generated by npm run ingest
```

No server-side logic required — any static host (S3, GitHub Pages, Nginx) works.

## `audit.json` schema

```jsonc
{
  "meta": { "tenant", "baseUrl", "dateMin", "dateMax", "total",
            "eventTypes", "namedActors", "days" },
  "cats":    ["Access Control", "Config", ...],          // sorted category names
  "types":   ["applications.assign", ...],               // sorted event type strings
  "typeCat": [4, 5, ...],                                // index into cats[] per type
  "users":   ["Alice Smith", ..., "Unresolved / System"],// sorted display labels
  "named":   [1, 0, ...],                                // 1=named identity, 0=system/UUID
  "events":  [["2026-05-01T10:00:00", typeIdx, userIdx, {dataObj}], ...]
}
```

## Dashboard features

- **KPI strip** — Total events, Scans created, Projects created, Logins (OK/FAIL split), Failed logins (amber warning), Source-code downloads (red alert)
- **Sticky breadcrumb filter bar** — drill path `All events › Category › Event Type › Actor › Day`; each level is a removable chip; free-text search across all fields
- **Adaptive drill chart** — doughnut (by category) → horizontal bars (event types → actors → actor's type mix); click to drill, breadcrumb to step back
- **Top Actors** — named identities by event count within scope; click to filter; selected actor highlighted in orange
- **Activity Timeline** — daily bar chart zero-filled across full date range; click to toggle day filter
- **Hourly Distribution** — 0–23 UTC event count
- **Event Log** — sortable, paginated (100/page), expandable rows showing full data record; newest-first default

## Tech stack

- **Vite 8** + **TypeScript** (vanilla, no framework)
- **Chart.js 4** — only runtime dependency
- **vite-plugin-singlefile** — inlines JS/CSS into one HTML file at build time
- **Vitest** — unit tests for parser and category map
